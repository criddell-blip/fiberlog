Rebuilding the Inventory tab

Scope, sequencing, and effort for shipping the Console direction — sidebar navigation, a light system, a real icon set, and responsive desktop + phone layouts — as production UI.

01 · What we're fixing
Emoji → icon system
Every emoji replaced with one consistent line-icon set, so a glyph means the same thing everywhere and reads as a real product.
Navigation ≠ actions
Sub-tabs move into a left sidebar (a drawer on phone); the seven “do something” actions live in one toolbar / sheet. No more mixing the two rows.
Light, modern surface
A calm slate + emerald palette, tighter type scale, and a proper data table replace the current dark card stack.
Genuinely responsive
Each view defines a desktop table and a phone card layout from the same data — not a single layout that degrades.

03 · Approach
A
System first. Lock tokens, the icon set, and a handful of shared primitives (button, badge, table, card, sheet, sidebar) before touching screens. Everything after reuses them.
B
Stock is the template. It's the most-used view and exercises the table↔card, filters, and bulk-select patterns. Nail it once; the other tabs inherit the recipe.
C
Ship behind a flag, tab by tab. The redesign can run next to the current UI per-view, so nothing big-bangs and QA stays focused.

06 · Assumptions & what could move it
·
Data & logic stay put. This is presentation only — no schema, RPC, or business-logic changes. If we touch data flows, add time.
·
Inventory tab only. The crew app, admin, reports, and approvals are separate efforts — likely 2–3× this combined once the system exists to reuse.
·
Dark mode is a decision. Keeping full light+dark parity adds roughly 15–20%. Recommend shipping light-first, dark as a fast-follow.
·
Estimates are working ranges for one experienced React/front-end dev, excluding code review and release process.
