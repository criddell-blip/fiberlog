# FiberLog change history

> Moved out of CLAUDE.md (July 2026). Historical record of major work.

- **Installer stock-first crew shell + Common items (Aug 21 2026):** `crew_type='install'` users (5 crew + the owner's own working-manager account) were landing in the full project→phase→task `CrewApp` although installers log jobs in Sonar and only use FiberLog for truck stock. New `isStockFirstCrew()` / `STOCK_FIRST_CREW_TYPES = ['install']` in `lib/crewTypes.js`; `CrewApp` reads it and makes **My Stock the home screen** (narrow + wide), folds the project tree behind a "Projects" sidebar entry / "Projects →" link (owner chose keep-reachable over remove), and inverts the Back-button depth maps so My Stock is depth 0. `MyStockView` gained an owner-curated **Common items** quick-load strip: every active `assemblies.crew_type='install'` assembly's parts (flattened in sort order, deduped by SKU) render as chips with on-hand-on-truck (zero dimmed, not hidden); tap → Load sheet pre-filled. `CrewMovementSheet`'s `prefillPartId` now works in load mode (seeds the by-part search with the SKU; auto-picks when the part is stocked at exactly one loadable source). The Assembly editor's Install tab says so (replacing a stale "currently unused — blocked on Sonar polygons" note). No schema / RLS / RPC change; fiber + infra crews unaffected. Known pre-existing gap: `ensure_crew_truck()` doesn't fire when a crew_type is added after user creation, so an installer without a truck row sees the existing "no truck yet" empty state.

- **Field-tech routing blocker retired — it had already resolved itself (Aug 14 2026):** Docs said field-tech Sonar import was blocked waiting on Sonar polygon/address → region data. Investigating a request to "reimport the project addresses" showed the premise was stale: **Option 3 (dispatcher tags the project at job creation) is live in Sonar**, and FiberLog already consumes it. Evidence: the daily "Field tech asset consumption" report carries a `Project` column on fiber jobs, and `sonar_project_phase_map` resolved **52/53** distinct tags in the owner's 8,289-row "Fiber project addresses" export; adding the one gap (`COLDER SPRINGS` → existing Cold Springs phase — verified a distinct Lehi buildout, not a typo: 24 vs 12 street names, 1 in common) took it to **53/53 = 100%**. The ~51% of report rows with a blank `Project` are **wireless**, not missing data — confirmed by equipment model (tagged = GP1100X / GP4200XH / UFiber / Wave-Fiber-ONU; untagged = Wave LR / Nano / Pico, PowerBeam, NanoStation) — and route by the wireless part policy shipped in `e319d2c`. Only **6 fiber rows in all of Q2** were untagged. **Confirmed we should NOT build an address → project lookup table:** cross-checking the owner's address export against the daily report, on the 759 rows where both carried a value the two **agreed 759/759, zero disagreements** — the table would change no routing decision. Also debunked a long-standing assumption that a serviceable-address list had been loaded: no such table exists in any of the 37 public tables; two empty placeholders (`sites.address`/`lat`/`lng` NULL on all 198 rows, `projects.vetro_project_id` NULL on all 7) made the plumbing merely *look* present. Noted `sonar_city_bucket_map` (3 rows) as the weak legacy fallback — city granularity mis-routes Provo, which spans Wasatch Front and West Mountain. Changes: one additive prod row in `sonar_project_phase_map`; docs corrected in CLAUDE.md (crew-workflow table, "Why this split", the former "Field tech (backlog — blocked)" section, the Sonar-routing "Future:" note) and `docs/BACKLOG.md` (#3 closed, #6 unblocked). No code changed.
- **Manager edit-then-approve + crew flag-restore (July 2026):** Fixing wrong materials no longer requires flagging a passdown back to the crew. **(A)** Managers can edit a **pending** submission's parts (qty / add / remove) and hours in the `SubmissionsQueue` detail overlay (**"Edit materials & hours"**), then Approve — `approve_submission` reads the live `entry_parts`, so the deduction reflects the edits. New `replace_submission_parts` RPC (SECURITY DEFINER, `is_staff()`-guarded, pending-only via `actuals_applied_at`, submission-scoped; consolidates parts onto one linked `log_entry`, branches for part-less + legacy-unlinked entries). Only `entry_parts` change — footage/`total_*` rollups and phase actuals untouched; hours writes `submissions.hours_worked` (`work_sessions.hours_worked` is dead). UI reuses crew tally steppers + the `PartSearch` overlay; dirty edits confirm on Back/Cancel (`useBackClose`). Helper `saveSubmissionParts` in `lib/supabase.js`. Flag stays for genuine send-backs. Migration `20260714120000_replace_submission_parts.sql`. Verified: DB tests (consolidation, both fallback branches, sibling isolation, approved/non-staff guards), full money-path (edit → approve posts `transfer` movements with edited quantities + deducts stock), security advisor clean, code review (verdict ship), and an operator UI run (8/8 steps). **(B)** When a flag *is* used, `TaskWorkspace` now restores the flagged passdown's materials into the crew's editable draft on reopen (was empty because submit resets `working_counts`), so the crew edit the fix instead of re-typing it. Also fixed the crew "Add part not in list" flow: extra parts gained ± quantity steppers (were stuck at 1) and re-adding a part increments instead of duplicating.
- **Full-access manager toggles + aerial/underground merge (June 2026):** Two owner requests. **(A) Opened three formerly owner-only inventory toggles to all staff (owner + manager)** — inventory pause/resume (`AdminPanel` + crew-visible `PausedBanner`, the latter now gated on `isStaff`, not unconditional), the per-user Load-destinations whitelist (`AdminUsersView` `LoadDestinationsSection`), and location/bin retire (`InventoryLocationsTab` + `LocationDetailPanel`). The **Admin tab itself** is now visible to all non-restricted staff (was owner-only in `ManagerApp`), otherwise managers couldn't reach AdminPanel/Users at all. DB: RLS write policies on `app_settings` + `crew_load_destinations` flipped owner→`is_staff()`. **The owner/manager boundary is now solely owner-account minting** — `cannotPickOwner` (UI) + `admin-create-user` (server) stay owner-locked. A warehouse-manager hire is created as `restricted_to_inventory = true` (Inventory tab only; reaches retire but not pause/load-dest, which live under Admin — acceptable, benefits full managers). Reachability caveat documented. **(B) Merged crew types `aerial` + `underground` → `fiber_construction` ("Fiber construction")** on the WORKER-CLASSIFICATION axis only (`users.crew_type` + `crew_type_part_restrictions`). DB: both CHECKs widened (legacy aerial/underground kept valid), 11 users migrated (8+3), restriction rows deduped 8→4, `approve_submission` guard gained `fiber_construction`. JS: `crewTypes.js` (`VALID_FIELD_CREW_TYPES` + new `crewTypeLabel()`/`CREW_TYPE_DISPLAY`), `admin.js`, `AdminUsersView` (options / `crewTypesFromName` / default), `CrewTypePermissionsView`, `ManagerApp` tooltip, `App.jsx` comments; `CrewStatus` + `CrewApp` render via `crewTypeLabel()`. The WORK-LOGGING axis (`assemblies.crew_type`, `tasks.task_type`, the aerial/footage/splice/underground workspace tabs) was deliberately NOT touched — fiber crews keep the same 4-tab strip. Both DB migrations were applied via MCP and recorded in remote history; the local `supabase/migrations/` files (`…_open_owner_toggles_to_staff.sql`, `…_merge_aerial_underground_fiber_construction.sql`) exist for parity only (`db push` skips them).
